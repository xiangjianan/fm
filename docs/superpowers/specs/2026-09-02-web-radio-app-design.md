# 网页版电台应用（复古收音机）设计文档

- 日期：2026-09-02
- 状态：已确认（用户于本日批准方案 A 与设计细节）
- 项目目录：`/Users/xiangjianan/github/fm`

## 1. 背景与目标

做一个可通过 Wi-Fi 在线收听中国各省 FM 电台的网页应用（网络电台，非调频解调）。
用户无苹果开发者账号，放弃原生 iOS 路线，选择网页（PWA 风格），理由：

- Safari 原生支持 HLS（m3u8）播放，零依赖即可拉流；
- 添加到主屏幕后接近原生体验，锁屏可继续播放；
- 零成本、免审核、全平台（iOS/Android/桌面）可用。

**成功标准**：双击打开 `index.html`，3 次点击内听到任意省份电台直播；主流浏览器与 iOS Safari 锁屏播放正常。

## 2. 已确认的关键决策

| 决策项 | 选择 |
|---|---|
| 电台范围 | 中央 + 31 个省级行政区，每省 2~4 个主频率，共约 90~110 台 |
| 技术形态 | 单文件 `index.html`（零构建、零后端、零依赖安装） |
| 界面风格 | 复古收音机（木纹 + 奶油色面板、调频刻度盘、指针、VU 律动条、旋钮） |
| 架构方案 | A：纯前端单文件 + 内置静态数据（可平滑升级到探活服务/流代理） |
| 验证方式 | 流探活脚本 + 手动 E2E（对全局 80% 测试覆盖规则的有意偏离，已获用户确认） |

## 3. 架构

```
┌─────────────────── index.html（单文件） ───────────────────┐
│                                                            │
│  数据层    STATIONS 数组内嵌（中央 + 31 省级行政区）          │
│              └─ id / name / frequency / region /            │
│                 url（优先 https）/ urlBackup（可选）          │
│                                                            │
│  播放层    单个 <audio> 实例                                │
│              ├─ Safari：原生播 HLS（m3u8）                  │
│              ├─ Chrome/Firefox/Edge：hls.js（CDN 引入）      │
│              └─ 重试策略：失败重试 2 次（指数退避）→          │
│                 换 urlBackup → 「无信号」状态                │
│                                                            │
│  UI 层     复古收音机面板（手机优先，桌面居中 ~480px）        │
│              ├─ 调频刻度盘 87.5–108 MHz + 指针               │
│              ├─ 液晶屏（台名/频率/状态 + VU 动画）            │
│              ├─ 省份频段按键（录音机推子风格）+ 电台列表        │
│              ├─ 搜索、收藏（localStorage）、音量旋钮           │
│              └─ Media Session API（锁屏台名，iOS 16.4+）      │
└────────────────────────────────────────────────────────────┘
        │
        ▼ HTTPS/HTTP 音频流
  各电台/融媒体官方 CDN（cnr.cn 等公开直播源）
```

无后端。流地址失效时更新 HTML 内嵌数据即可。

## 4. 数据层设计

- 内嵌常量 `STATIONS`，按省份分组的对象数组，顺序：中央在前，其余 31 个省级行政区按名称拼音升序排列。
- 每台字段：
  - `id`：稳定标识（拼音或 slug），用于收藏去重；
  - `name`：显示名（如「中国之声」）；
  - `frequency`：FM 频率显示值（如 106.1）；无公开 FM 频率的纯网络台固定填 `99.0`，指针统一落到刻度盘中段；
  - `region`：省份/「中央」；
  - `url`：直播流地址，优先 https、优先验证过 CORS 与可播性的地址；
  - `urlBackup`：可选备用流。
- 收录标准：实现前用 `curl` 逐个验证（HTTP 200 / 音频数据可达），**只收录验证通过的流**；验证结果记录在探活脚本输出里。
- 已知风险：公开流会改版失效；http-only 流在 https 部署（如 GitHub Pages）下会被混合内容拦截——因此优先收录 https 流，本地 `file://` 打开则不受此限制。

## 5. 播放层设计

- 全局唯一 `<audio>` 元素，切台即换源，避免多实例竞态。
- 播放源协商：
  1. 浏览器为 Safari（或流为 progressive aac/mp3）→ 直接 `audio.src`；
  2. 否则若 `Hls.isSupported()` → hls.js 挂载；
  3. hls.js CDN 加载失败且非 Safari → UI 明确提示「请用 Safari 打开或检查网络」。
- 状态机：`idle → loading → playing ⇄ paused / error`；error 进入重试流程（2 次，1s/3s 退避），重试耗尽换备用地址，再失败展示「无信号」+ 手动重试按钮。
- Media Session API 设置台名/频率与播放暂停控件（能力检测，缺省不报错）。
- VU 律动条为纯 CSS/JS 动画模拟（真实 AnalyserNode 需流端 CORS 解锁音频数据，不可靠，明确不做）。
- 音量：`audio.volume` 映射到旋钮角度（0–270°），iOS Safari 不允许脚本控音量时降级为系统音量提示。

## 6. UI 层设计

- 布局：移动优先（≤480px 全宽）；桌面居中一个 480px 宽「便携收音机」面板。
- 视觉：木纹边框（CSS 渐变模拟）、奶油色面板、暖橙点缀；刻度盘白底黑字；液晶屏暖绿/琥珀字。
- 组件：
  - **刻度盘**：87.5–108 MHz 线性刻度；选台后指针（CSS transform）平滑滑到该台 `frequency` 对应位置；
  - **液晶屏**：台名、频率、region、状态（调谐中…/播放中/已暂停/无信号）+ VU 条；
  - **频段按键**：中央、京、沪、粤…横向滚动推子键，选中下陷高亮；
  - **电台列表**：当前省份的电台行（台名 + 频率 + 收藏星标 + 播放按钮），正在播放行高亮；
  - **搜索**：按台名/省份过滤，覆盖全部数据；
  - **收藏**：星标切换，顶部「收藏」频段键查看；存 localStorage（key: `fm-favorites`）。
- 交互细节：切台即播（点列表行 = 播放）；播放中再点暂停；空格键播放/暂停（桌面）。

## 7. 错误处理

- 流失败/断流：按第 5 节重试链路，最终「无信号」态可手动重试。
- hls.js 加载失败：非 Safari 下明确提示。
- localStorage 抛异常（隐私模式）：收藏降级为内存态，界面不崩。
- 自动播放被拦截：一切播放均由用户点击触发（浏览器手势要求），不尝试自动恢复播放，仅恢复到 paused 态。

## 8. 验证方式

1. **探活脚本** `tools/check-stations.sh`（curl 逐个验证流的可达性/HTTP 状态/是否 https/CORS 头），开发期跑，产出报告供人工筛除死链。
2. **手动 E2E 清单**：
   - macOS Safari / Chrome：打开页面、切 3 个省的台、音量旋钮、搜索、收藏刷新后保留；
   - iPhone Safari：添加到主屏幕、锁屏播放不断、锁屏显示台名；
   - 断网/死链台：出现「无信号」与重试，不白屏。
3. 不写单元测试（单文件无构建/测试基建；已与用户确认此偏离）。
